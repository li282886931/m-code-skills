# Mcd Order Detective — 麦当劳订单侦探

## Overview

像侦探一样审视用户的麦当劳消费历史，从订单数据中挖掘隐藏的模式和故事。构建用户的"口味画像"，发现消费趋势，给出有洞察力的分析和个性化推荐。让用户看到自己平时看不到的消费真相。

## Core Capabilities

### 1. 历史订单全景分析

调用 `order-list` 获取全部历史订单，逐条调用 `query-order` 获取详情，汇总分析：

**消费统计面板**：
- 总消费金额 / 订单总数 / 平均客单价
- 最常点餐品 Top 5（按频次）
- 消费最高的单笔订单
- 最近一次消费距今时间

**消费趋势**：
- 按月统计消费金额变化（上升/下降趋势）
- 按时段分析（早/午/晚/夜宵）下单偏好
- 按场景分析（到店/外送/得来速）占比

### 2. 口味画像构建

从历史订单的餐品组合中提炼用户的口味偏好：

- **口味标签**：如"嗜辣型"(常点麦辣系列)、"肉食系"(常点安格斯/巨无霸)、"甜品控"(常点麦旋风/圆筒)、"咖啡依赖"(常点麦咖啡)
- **搭配习惯**：如"汉堡必配薯条"、"无饮不欢"、"甜品+咖啡"
- **价格偏好**：如"高性价比"(常点随心配/1+1)、"品质优先"(常点安格斯/套餐)
- **探索指数**：常点餐品种类数 / 总订单数，判断用户是"保守型"还是"冒险型"

### 3. 消费洞察报告

生成有洞察力的分析报告，格式参考：

```
📊 麦当劳消费档案

你在麦当劳消费了 XX 笔订单，总计 ¥XXX
平均每单 ¥XX，最贵的一单花了 ¥XX

🏆 你的最爱 Top 3：
1. 麦辣鸡腿堡三件套（点了 X 次）
2. 巨无霸三件套（点了 X 次）
3. 薯条（点了 X 次）

🔍 侦探发现：
- 你是一个"嗜辣型"食客，X% 的订单包含辣味产品
- 你偏爱晚餐时段，X% 的订单在 17:00-21:00 下单
- 过去 3 个月消费趋势：上升/下降/平稳
- 你的探索指数 X%，属于"保守型/冒险型"食客

💡 换个口味试试？
基于你的口味画像，推荐试试：
- XX（与你的偏好相似但没点过的餐品）
- XX（同口味分类下的新品）
```

### 4. "换个口味"智能推荐

基于口味画像，推荐用户**没点过但很可能喜欢**的餐品：
1. 提取用户常点餐品的 tags（如"辣"、"100%纯牛肉"、"套餐"）
2. 调用 `query-meals` 获取全量菜单
3. 筛选 tags 重合度高但用户从未点过的餐品
4. 调用 `list-nutrition-foods` 补充营养对比
5. 推荐 2-3 个"新尝试"选项，附推荐理由："你喜欢麦辣鸡腿堡(辣味)，试试龙焰鸡腿堡？同样是韩式辣椒黄油风味，上新新品"

### 5. 商城订单分析

调用 `mall-order-list` + `mall-order-detail` 分析积分兑换记录，展示：
- 累计兑换商品数
- 兑换的商品类型分布（餐品券/实物/周边/派对）
- 积分使用效率评估

## Workflow

```
用户想看消费分析
    │
    ├─ order-list → 获取历史订单列表
    │     └─ query-order(逐条) → 获取每个订单详情
    │
    ├─ 数据聚合分析 → 生成统计面板 + 口味画像 + 消费洞察
    │
    ├─ mall-order-list → 商城订单分析
    │
    ├─ query-meals + list-nutrition-foods → "换个口味"推荐
    │
    └─ 输出消费洞察报告
```

## Important Rules

- `order-list` 返回的订单需逐条用 `query-order` 获取详情才能看到餐品明细
- 历史订单数据量可能较大，需做好分页和聚合，避免一次性展示过多原始数据
- 口味画像的标签判断需基于足够样本（至少3笔订单），样本不足时提示"数据量较少，画像仅供参考"
- 推荐时避免推荐用户明确不喜欢的产品（如从未点过甜品类且消费偏好为肉食系，不推荐甜品）
- 商城订单(`mall-order-list`)和餐品订单(`order-list`)是分开的，需分别查询
- 分析结果以报告形式展示，重点突出"侦探发现"部分的洞察，而非简单罗列数据
