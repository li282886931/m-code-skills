# Mcd Social Feast — 麦当劳社交聚餐管家

## Overview

解决麦当劳多人点餐的痛点：每个人想吃的都不一样，分开点配送费太贵，一起点又众口难调。本技能收集所有参与者的口味偏好和忌口，在共享菜单中找到最大公约数，生成兼顾众人的优化方案，最后统一下单配送到一个地址。

## Core Capabilities

### 1. 多人偏好收集

通过对话逐个收集参与者信息：
- 每人想吃的餐品/品类（汉堡/炸鸡/甜品/饮料）
- 忌口/过敏（不要辣/不要牛肉/不要海鲜）
- 预算上限（每人XX元）
- 特殊需求（加酱/不要洋葱/大份）

展示收集进度：
```
👥 聚餐人数：3人

👤 小明：想吃巨无霸，不要酸黄瓜，预算40
👤 小红：想吃炸鸡+甜品，忌辣，预算35
👤 小李：随便都行，预算30
```

### 2. 众口协调方案

基于多人偏好，调用 `query-meals` 获取菜单，生成协调方案：

**策略 A：求同存异**
- 找到大家都接受的共性餐品（如薯条/麦乐鸡/饮料作为共享项）
- 每人单独的主食满足个人偏好
- 计算总价，按人均分摊

**策略 B：套餐最大化**
- 选择覆盖面最广的多人套餐/拼盘（如全明星双人分享餐八件套、堡堡随心拼）
- 补充个人偏好单品
- 利用套餐优惠降低总成本

**策略 C：分治方案**
- 如果偏好差异太大无法协调，分成2-3个子订单
- 但共享配送地址，省配送费

每个策略展示：商品列表、总价、人均费用、满意度预估

### 3. 配送地址管理

调用 `delivery-query-addresses` 查询用户已有地址，或调用 `delivery-create-address` 创建新地址：
- 确认聚餐地点（办公室/家里/公园旁）
- 确认联系人信息
- 确认配送方式（麦乐送 beType=2 / 团餐 beType=6）

### 4. 最优价格计算

调用 `query-store-coupons` 查询门店可用券，调用 `auto-bind-coupons` 先一键领券，再调用 `calculate-price` 计算最优价格：
- 遍历可用优惠券，找最低价组合
- 检查随单购优惠
- 比较套餐vs单品

### 5. 统一下单与分摊

确认方案后：
1. 调用 `calculate-price` 确认最终价格
2. 展示分摊明细（每人应付金额）
3. 调用 `create-order` 创建订单
4. 引导支付

分摊计算规则：
- 共享项（薯条/饮料）按人头均分
- 个人项由个人承担
- 配送费按人头均分
- 优惠券折扣按比例分摊

## Workflow

```
用户要组织多人聚餐
    │
    ├─ Step 1: 收集参与者偏好（逐个询问）
    │
    ├─ Step 2: delivery-query-addresses / delivery-create-address → 确认配送地址
    │          └─ delivery-query-stores → 获取可配送门店
    │
    ├─ Step 3: query-meals → 获取菜单
    │          └─ 生成 3 个协调方案（求同存异/套餐最大化/分治）
    │
    ├─ Step 4: auto-bind-coupons → 一键领券
    │          └─ query-store-coupons → 查门店可用券
    │          └─ calculate-price → 计算最优价格
    │
    ├─ Step 5: 展示分摊明细 → 用户确认
    │
    └─ Step 6: create-order → 创建订单 → 引导支付
```

## Important Rules

- 参与者偏好必须逐个确认，不可自行假设
- 如果出现无法协调的矛盾（如一人要辣一人忌辣），在方案中明确标注冲突并给出折中建议
- 团餐场景(beType=6)需先调用 `query-meal-assistance` 获取助餐服务
- 分摊计算需精确到分，避免四舍五入误差
- 配送费按 `calculate-price` 返回的实际费用计算
- 如果总预算不足以覆盖方案，提示"预算不足，建议方案调整"并给出缩减建议
- 人多时(>6人)建议拆分为团餐场景(beType=6)
